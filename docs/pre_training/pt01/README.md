# PT-01 — Self-distilled pilot vs BP-09 (Qwen3-1.7B)

Status: **final (2026-11-06): GO for PT-02.** Plan: [`../PLAN.md`](../PLAN.md).

**Question (RQ1).** Starting from BP-09, does a Qwen3-1.7B draft trained on the **target's own answers** reach a
higher acceptance length than BP-09, which was trained on the **original ShareGPT answers** of the same 900
conversations?

| arm | train data | checkpoint |
|---|---|---|
| **A0** (BP-09) | 900 chat, ShareGPT answers, 8 ep | BP-09 Kaggle run (results in `mini_aurora/zaratan/results/1p7b/`) |
| **A1** (this run) | same 900, every assistant turn regenerated by Qwen3-1.7B, 8 ep | release [`pt01-a1-v1`](https://github.com/Gauravp2104/rl-spec-decoding/releases/tag/pt01-a1-v1) |

Everything else is identical to BP-09: draft config `examples/zaratan-qwen3-1.7b/draft_config.json`, 24K vocab,
aux layers 1 / 13 / 24, fp32 + gradient checkpointing, LR 1e-4, batch 2 × 4, 896 steps, seed 0, Kaggle T4.

## Results (held-out chat, `chat-00900` … `chat-00999`, greedy, K = 3, 128 new tokens)

| metric | A0 (BP-09) | A1 (self-distilled) | Δ |
|---|---|---|---|
| τ̄ | 0.319 | **0.473** (95% CI 0.447–0.499) | **+0.154** |
| α1 / α2 / α3 | 0.244 / 0.059 / 0.015 | 0.328 / 0.109 / 0.036 | +0.084 / +0.050 / +0.021 |
| lossless | 100/100 | **100/100** | |
| teacher-forced acc, pos 1 / 2 / 3 | 0.354 / 0.292 / 0.260 † | 0.403 / 0.340 / 0.307 ‡ | |
| tok/s (T4, fp32, spec) | 12.0 | 13.2 (target-only ≈ 23) | |
| train-split assistant tokens | 367K | 442K | +20% |

A0 numbers are BP-09's recorded results (`mini_aurora/zaratan/results/1p7b/`). † on the ShareGPT held-out dump;
‡ on the self-distilled held-out dump, so the two accuracy rows are **not directly comparable**. The CI is a
2,000-sample bootstrap over the 100 requests (`mini_aurora.eval.metrics.tau`).

**Why BP-09's recorded numbers are a valid baseline.** Both arms ran the same path on the same hardware: Kaggle T4,
`serve -n 100 --heldout --check` (`run_pt01.py` is a clone of `run_bp09.py`), the same 100 held-out IDs, the same
target and aux layers. The serve code was last changed on 2026-10-28, before BP-09 ran (2026-10-29/30). Greedy
serving with the same code, checkpoint and requests is essentially deterministic, so a same-session re-run of A0 is
not needed for the decision; it moves to PT-02's evaluation (optional, if the BP-09 checkpoint is recovered).

Held-out accuracy per epoch (A1, self-distilled dump) plateaus after epoch 5:

| epoch | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| acc pos 1 | 0.257 | 0.326 | 0.360 | 0.380 | 0.394 | 0.401 | 0.403 | 0.403 |
| acc pos 3 | 0.120 | 0.226 | 0.264 | 0.288 | 0.303 | 0.306 | 0.307 | 0.307 |

**Decision: GO for PT-02.** A1 beats A0 by +0.154 τ̄, about 7× the 0.02 go threshold (PLAN §8), and the lower CI
bound (0.447) is far above 0.319, so no second seed is needed. As hypothesised (PLAN §2), the relative gain grows with
position: α1 ×1.3, α2 ×1.8, α3 ×2.4.

## Self-distilled data (`a1_8ep_seed0/chat_self_1p7b.stats.json`)

| | ShareGPT (A0) | regenerated (A1) |
|---|---|---|
| conversations | 1000 | 1000 (same ids and order) |
| assistant turns | 1,929 | 1,336 |
| assistant tokens | 401K | 484K |
| mean answer length (tokens) | 208 | 363 |

- 47% of regenerated answers hit the 512-token cap; 1.7% were flagged as looping.
- The 1024-token conversation cap cut 593 later turns in 399 conversations, so A1 is mostly single-turn.
- 50 duplicate answers, all from repeated ShareGPT prompts (e.g. 23× "Hello! How can I assist you today? 😊").
- Regeneration took 2.4 h on the T4 (batch 16), dump 17 min, training 1.5 h, serving 24 min.

## Caveats

1. **A0 not re-measured in this session**: the 0.319 comes from the BP-09 run (same harness, code and hardware
   type; see above). Not re-measured: teacher-forced accuracy of both arms on the same dump, code / math
   out-of-domain checks, measured speed-up.
2. **More training text in A1**: 442K assistant tokens in the train split vs A0's 367K (+20%). This cannot explain
   the gap: on 0.6B, 10× more data (900 → 9K conversations) added about +0.31 τ̄, so +20% would add a small
   fraction of +0.154.
3. **Truncated answers**: a capped answer still gets an end-of-turn label where it was cut. For PT-02, raise
   `--max-new-tokens` or keep capped turns out of the loss.
4. **Single seed**: seed variance is not measured; `push_pt01 --seed 1` reruns A1.
5. **No speed-up on a T4 in fp32**: drafting overhead outweighs τ̄ ≈ 0.47; τ̄ is the primary metric.
