# PT-03 — Tree drafting on A0, A1 and the 0.6B 15K draft

Status: **draft, waiting for B1 (PT-02).** Plan: [`../PLAN.md`](../PLAN.md), optional serve-only arm.

**Question.** Does the self-distillation gain (PT-01, +0.154 τ̄ on a K = 3 chain) carry over when the draft proposes
a tree instead of a chain, and how does the 1.7B target compare with the 0.6B target under the same tree settings?

| draft | target | train data | checkpoint |
|---|---|---|---|
| **A0** (BP-09) | Qwen3-1.7B | 900 chat, ShareGPT answers, 8 ep | BP-09 Kaggle run (`rl-spec-decoding-bp09-1p7b`) |
| **A1** (PT-01) | Qwen3-1.7B | same 900, answers regenerated by Qwen3-1.7B, 8 ep | release [`pt01-a1-v1`](https://github.com/Gauravp2104/rl-spec-decoding/releases/tag/pt01-a1-v1) |
| **15K/6ep** (BP-04, #33) | Qwen3-0.6B | 15,000 chat, ShareGPT answers, 6 ep | BP-04 Kaggle run (`rl-spec-decoding-bp04-15k-6ep`) |

No retraining. Each draft is served on the same 100 held-out chat requests (`chat-00900` … `chat-00999`) with
`serve -n 100 --heldout --check -k 3`, greedy, 128 new tokens, fp32, Kaggle T4, at the chain and the plan's four tree
settings `--tree-topk {2,4} --tree-beam {2,4}`. `serve.py` clamps `--tree-beam` to at least `--tree-topk`, so
top-k 4 / beam 2 runs as beam 4 and is the same setting (its files are kept for completeness).

## Results (τ̄, K = 3, all 15 serves 100/100 lossless)

| draft | chain | top-k 2 / beam 2 | top-k 2 / beam 4 | top-k 4 / beam 4 | Δ chain → top-k 4 |
|---|---|---|---|---|---|
| A0, 1.7B BP-09 | 0.319 | 0.430 | 0.445 | **0.533** | +0.214 (×1.67) |
| A1, 1.7B self-distilled | 0.473 | 0.618 | 0.649 | **0.744** | +0.271 (×1.57) |
| 15K/6ep, 0.6B | 0.671 | 0.877 | 0.933 | **1.059** | +0.388 (×1.58) |

The chain rows reproduce the recorded numbers (BP-09 0.319, PT-01 0.473, #33 0.671), so the tree rows are on the same
footing as the earlier results.

Per-position acceptance α1 / α2 / α3 and T4 throughput (tok/s, fp32 target, speculative):

| draft | chain | top-k 2 / beam 2 | top-k 2 / beam 4 | top-k 4 / beam 4 |
|---|---|---|---|---|
| A0 | 0.244 / 0.059 / 0.015 · 12.0 | 0.318 / 0.088 / 0.023 · 9.4 | 0.316 / 0.100 / 0.029 · 7.5 | 0.385 / 0.116 / 0.032 · 7.3 |
| A1 | 0.328 / 0.109 / 0.036 · 14.2 | 0.414 / 0.152 / 0.051 · 11.4 | 0.413 / 0.173 / 0.063 · 9.1 | 0.483 / 0.192 / 0.070 · 8.9 |
| 15K/6ep | 0.421 / 0.174 / 0.076 · 29.4 | 0.527 / 0.244 / 0.106 · 26.9 | 0.527 / 0.278 / 0.128 · 24.5 | 0.609 / 0.310 / 0.139 · 23.0 |

- **The self-distillation gain survives trees and widens**: A1 − A0 is +0.154 on the chain and +0.211 at top-k 4.
  Relative lift is about ×1.6 for all three drafts, so trees multiply whatever acceptance the draft already has.
- **Top-k matters more than beam**: going from top-k 2 to 4 at beam 4 adds +0.09 to +0.13; widening the beam from
  2 to 4 at top-k 2 adds only +0.015 to +0.056. α1 is unchanged by the beam, as expected (the beam only prunes
  depth ≥ 2).
- **The 0.6B 15K draft stays ahead of both 1.7B drafts** at every setting; it was trained on 17× more
  conversations.
- **Throughput falls on the T4** by 40% on the 1.7B drafts (12.0 → 7.3, 14.2 → 8.9) and 22% on 0.6B (29.4 → 23.0):
  an fp32 verify pass over the whole tree on a T4, not a deployment number. τ̄ is the primary metric.

Serve time per setting: 24–37 min for the 1.7B drafts, 14–16 min for 0.6B; about 2.5 h per 1.7B draft and 1.3 h for
0.6B on one Kaggle T4, no SU.

## Caveats

1. **B1 missing**: the plan's third tree arm is PT-02's 27K self-distilled 1.7B draft. The same runner serves it once
   #36 finishes (`push_pt03` needs a `b1` entry pointing at its checkpoint).
2. **Depth fixed at 3**: #34 showed depth helps on the 0.6B 9K draft (chain K = 5 0.647 vs K = 3 0.623; K = 6 top-k 3
   beam 8 reached 1.078). Deeper trees on the 1.7B drafts are not measured here.
3. **Single seed, 100 requests**: no CI on the tree rows; the per-request logs are in `*/serve_heldout.jsonl` for a
   bootstrap.
4. **Chat only**: no code / math out-of-domain serve.
